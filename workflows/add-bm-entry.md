# 위키 항목 추가하기

**목표:** BM 분류, 장르, 또는 프로토타입을 위키에 새로 추가한다.

**언제 쓰나:** 사장님이 "이 BM/장르/프로토타입 위키에 추가해줘" 또는 스스로 조사하다가 새 항목이 필요하다고 판단했을 때.

## 필요한 입력값

- 카테고리: `bm-catalog`(BM 종류) / `genres`(장르) / `prototypes`(만들어본 프로토타입) 중 하나
- 항목 제목 (예: "쿠폰형 할인", "수집형 RPG")

## 절차

1. **먼저 있는지 확인한다.** `docs/{카테고리}/index.md` 표를 보고 이미 있는 항목이면 새로 만들지 말고 그 파일을 고친다.
2. **파일을 만든다.** `tools/new_entry.py`로 템플릿에서 새 파일을 생성한다.
   ```
   python tools/new_entry.py bm-catalog "쿠폰형 할인" --slug coupon-discount
   ```
3. **내용을 채운다.** 템플릿의 모든 섹션(등장 배경/역사, 대표 사례, 적합한 재미 요소, 지양해야 할 상황, 파생형)을 채운다.
   - **사실관계가 불확실하면 반드시 "검증 필요"라고 표시한다.** 추측을 확정된 사실처럼 쓰지 않는다.
   - 역사/연혁 항목은 가능하면 웹 검색으로 연도·출처를 확인하고 채운다.
   - 최소 하나 이상의 관련 항목(다른 BM 또는 장르)으로 링크를 건다.
4. **상태를 갱신한다.** 파일 상단의 `**상태:**`를 뼈대 → 초안(핵심 내용 작성) → 완성(사실관계 확인 완료) 순으로 올린다.
5. **총람에 등록한다.** `docs/{카테고리}/index.md` 표에 새 행을 추가한다 (이름, 상태, 한줄 정의).
6. **빌드로 확인한다.**
   ```
   mkdocs build --strict
   ```
   오류 없이 끝나면 성공. 깨진 링크나 nav 오류가 있으면 여기서 잡힌다.
7. **커밋한다.** (사장님이 원격 push까지 요청한 경우에만 push. 로컬 커밋은 자유롭게.)

## 문제가 생기면

- `mkdocs build --strict`가 깨진 링크를 지적하면, 파일 경로나 slug 오타를 먼저 의심한다.
- 사실관계를 확인할 수 없는 항목은 억지로 채우지 말고 "검증 필요"로 남겨둔다. 틀린 내용을 확정처럼 적는 것보다 빈 칸이 낫다.
